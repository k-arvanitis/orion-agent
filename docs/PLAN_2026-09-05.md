# Orion — roadmap to a production-grade customer support agent

Date: 2026-09-05
Status of repo at time of writing: code green (ruff clean, 50/50 tests, CI green),
docs stale, eval numbers stale, Qdrant Cloud cluster unreachable.

Goal: Orion is the customer-support portfolio project. It must (a) be finalizable
this week with honest numbers, and (b) visibly scale to a real company: hundreds
of policy/help-center documents in mixed formats and a database with dozens of
tables, not 4 markdown files and 9 hand-written tables.

vault-rag stays the deep-retrieval showcase. Orion's story is: agent routing,
Text2SQL over real data, human handoff, and an eval you can defend. Retrieval
here stays simple on purpose (hybrid dense+BM25, RRF). No HyDE, no reranker.

### Scale blockers found in code (why Phase 3 exists)

| Where | Problem at real-company scale |
|---|---|
| `sql_tool.py` `SCHEMA` | Hardcoded string, every table on every call. 50+ tables blows the prompt and degrades SQL accuracy. |
| `support_store._match_customer_from_message` | Loads every customer and every order into Python and substring-scans per message. O(customers + orders) per turn. Dies at 10k rows. |
| `support_store._is_policy_question` | Keyword heuristic left over from the rule engine, still on the identity path. |
| `ingestion/chunker.py` | Splits on H1/H2/H3 only, no size cap, markdown only. A 30-page PDF section becomes one chunk. |
| `ingestion/ingest.py` | `recreate_collection` drops everything on every run. No incremental update, no deletion of stale docs. |
| `rag_tool.py` | Fixed TOP_K, no metadata filter, no "nothing relevant" threshold. Returns 4 chunks even when the answer is not in the corpus. |
| `graph.py` | No `PROMPT_VERSION`, no `run_name`/`tags`/`metadata` on invoke. Eval results not tied to prompt version. |
| `api/main.py` | No auth on any endpoint. `escalate_to_human` posts to Slack, so an open endpoint is a spam vector. |
| Checkpointer | `SqliteSaver`, one local file. Single instance only. |

## Explicitly not doing

- HyDE, rerankers, query rewriting. `rag_only` is at 0.96; retrieval is not the failure surface and vault-rag owns that story.
- Gmail / customer confirmation email. Removed on purpose, heavy OAuth footprint.
- Voice conversation mode. Dictation stays as is.
- CRM connectors (Zendesk, HubSpot). No market signal for one specific vendor; "structured customer-data lookup over your DB" covers the pitch.
- Multi-tenant isolation. `tenant_id` field reserved in payload, nothing else. Single-tenant deployment is the honest claim.
- Numeric fact cross-checking. Stays in Known limitations.

response shape, same `TechnicalDetails` trace payload (tools called, SQL,

Re-record the video only if you do those two. Otherwise the current video
